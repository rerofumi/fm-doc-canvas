# FM Doc Canvas リファレンスマニュアル

[日本語](reference.md) | [English](reference_en.md)

この文書は、FM Doc Canvas v0.6.0 の GUI から利用できる機能をまとめた操作リファレンスです。2026-11-23 時点の実装に基づいています。

## 1. アプリの目的

FM Doc Canvas は、テキストや画像を無限キャンバス上に配置し、有向エッジで連結しながら思考や資料を整理するデスクトップアプリです。選択したノードと上流のつながりからコンテキストを収集し、OpenAI 互換の LLM（Vision・ローカル LLM を含む）や複数の画像生成プロバイダーへプロンプトを送信して、内容を要約・発展・視覚化できます。

キャンバスは思考や調査を行う一時的なワークベンチとして使い、完成した成果物は個別の Markdown（`.md`）、画像ファイル、または Marp プレゼンスライド（`.md`）としてエクスポートできます。

## 2. 画面構成

v0.6.0 では、ライトテーマを基調とした **Canvas-First / Low-Chrome** な UI を採用しています。常設サイドバーを置かず、必要なときだけオーバーレイを開く構成です。

### 2.1 メイン Canvas

ノードを配置、選択、移動、リサイズ、エッジ接続する作業領域です。

- 空白部分をドラッグ（または `Space` + ドラッグ）：キャンバスを移動（パン）します。
- マウスホイール：`0.1`〜`4.0` 倍（10%〜400%）の範囲で拡大・縮小します。
- OS からのドラッグ＆ドロップ：対応ファイルをドロップ位置へノードとして取り込みます。

### 2.2 上部フローティングバー

画面上部中央に配置されたツールバーです。

|項目|動作|
|---|---|
|`+ メモ`|キャンバス中央付近に空のテキストノードを追加し、選択状態にします。|
|`整頓`|エッジの接続関係を保ったまま、ノードを左→右（`LR`）方向へ自動整列し、全体表示します。|
|`開く`|保存済みの Canvas JSON（`.json`）を読み込みます。|
|`保存`|現在のキャンバスを `.json` ファイル（version `1.1`）に保存します。|
|`設定`|設定モーダルを開きます。|

画面右上には現在のズーム率（例：`100%`）が表示されます。クリックするとすべてのノードが収まるように全体表示（`fitView`）します。

### 2.3 下部コマンドドック ＋ コンテキストストリップ

画面下部中央に配置された AI 生成用の入力エリアです。

- **コンテキストストリップ**（ドック上部）：選択ノードと上流チェーンから収集されたコンテキスト件数を `コンテキスト: テキスト X件 / 画像 Y枚`（未選択時は `コンテキストなし`）としてリアルタイム表示します。上流探索中に分岐合流や循環を検出して探索を停止した場合は、警告チップが表示されます。
- **モード切替**：`テキスト`（LLM テキスト生成）と `画像`（マルチプロバイダー画像生成）を切り替えます。
- **プロバイダー切替**（`画像` モード時のみ）：`OpenRouter`、`OpenAI`、`Google`、`xAI` からそのリクエストで使うプロバイダーを選択します。ここでの変更は一時的なものであり、設定ファイルのデフォルトプロバイダーは書き換わりません。
- **プロンプト入力欄**：入力量に応じて自動で高さが広がります。`Ctrl+Enter`（macOS は `Command+Enter`）で送信できます。
- **`送信` ボタン**：プロンプトを送信します。実行中は `生成中` と表示され、多重送信を防ぎます。

### 2.4 テキストノード詳細エディタ（NodeInspector）

テキストノードをダブルクリックする（またはホバー時の `詳細を編集` ボタン／右クリックメニューの `編集` を選ぶ）と、画面右側からスライドインします。左端をドラッグしてパネル幅（`340px`〜`900px`、最大 `85vw`）を変更できます。

|項目|動作|
|---|---|
|`編集`|Markdown 本文を編集します。|
|`プレビュー`|GitHub Flavored Markdown（GFM）のレンダリング結果を表示します。|
|`Markdown 出力`|現在の本文（空の場合はサマリー）を `.md` ファイルとしてエクスポートします。|
|`×`|エディタを閉じ、編集内容を確定します。別ノードへ切り替えた場合も自動的に確定されます。|
|`サマリー`|カード上に表示する要約テキストです。直接編集できます（空の場合は本文先頭が表示されます）。|
|`サマリー生成`|現在の本文から LLM でサマリーを再生成します。|
|`元プロンプト`|AI 生成ノードにのみ表示されます。`入力欄へ追記` を押すと、コマンドドックの既存入力を消さずに末尾へ追記します。|

### 2.5 画像ライトボックス（ImageLightbox）

画像ノードをダブルクリックする（またはホバー時の `拡大表示` ボタン／右クリックメニューの `拡大表示` を選ぶ）と、拡大プレビュー用のモーダルが開きます。`×`、背景クリック、または `Escape` で閉じられます。

- ヘッダーには生成時のプロバイダー・モデル名（取り込み画像の場合はパス）と `画像をエクスポート` ボタンが表示されます。
- 生成画像の場合は下部に `生成プロンプト` 全文と `入力欄へ追記` ボタンが表示されます。

### 2.6 設定モーダル（SettingsModal）

上部バーの `設定` を押すと開きます。`LLM 設定`、`画像生成`、`キャンバス管理` の 3 タブで構成されます。詳しくは「8. 設定」を参照してください。

### 2.7 トースト通知・確認ダイアログ

処理の完了、警告（循環接続の拒否や分岐合流の検出など）、エラーは画面内のトースト通知で非ブロッキングに表示されます。`キャンバスを初期化` のような破壊的操作では確認ダイアログが表示されます。

## 3. ノードの種類

### 3.1 テキストノード

メモ、Markdown テキスト、AI の回答などを保持するノードです。

- カード上には、サマリーが設定されている場合は `要約` としてサマリーを、未設定の場合は `メモ` として本文を最大 8 行まで表示します。
- カードにマウスカーソルを合わせると、右上に `詳細を編集` と `ノードを削除` のアイコンが表示されます。
- AI が生成したノードの下部には `Prompt:` エリア（最大 3 行）が表示されます。クリックすると元プロンプトがコマンドドックの末尾へ非破壊で追記されます（既存入力がある場合は `\n\n` 区切り）。

### 3.2 画像ノード

ローカルファイルから取り込んだ画像、または AI が生成した画像を表示するノードです。

- 選択時に四隅・各辺のハンドルをドラッグしてサイズ変更できます（最小 `180×140`）。
- カードにマウスカーソルを合わせると、右上に `拡大表示` と `ノードを削除` のアイコンが表示されます。
- 生成画像の場合は下部に `Prompt:` とプロバイダー名バッジが表示され、クリックでコマンドドックへプロンプトを追記できます。
- LLM テキスト生成（Vision）や画像生成の参照コンテキストとして利用できます。

## 4. 選択・エッジ接続・コンテキスト収集

### 4.1 ノードの選択と削除

- クリック：1 ノードを選択します。
- `Shift` + クリック：複数ノードを追加・解除して選択します。
- `Shift` + ドラッグ：矩形選択で複数ノードをまとめて選択します。
- 空白部分をクリック：選択を解除します。
- `Delete` または `Backspace`：選択中のノードまたはエッジを削除します。

### 4.2 有向エッジの接続と循環防止

ノード右側の接続ハンドル（出力）から別ノード左側の接続ハンドル（入力）へドラッグすると、矢印付きの有向エッジを作成できます。

- 同じノード間の重複接続は作成されません。
- 自己ループや間接的なループ（循環）を形成する接続は作成前に検出され、警告トーストを表示して拒否されます。

### 4.3 コンテキスト収集の仕組み

コマンドドックから AI 生成を実行すると、選択状態と有向エッジに応じて次のようにコンテキストが収集されます。

|選択状態|収集ルール|
|---|---|
|0 件選択|キャンバス上のノードは含めず、コマンドドックの入力プロンプトのみを送信します。|
|1 件選択|選択ノードから入力エッジを上流へ遡り、源流 → 選択ノードの順でテキストと画像を分離収集します。途中で入力が 2 本以上に合流する分岐、または循環を検出した場合は、その手前までをコンテキストとして使用し、コンテキストストリップに警告を表示します。|
|2 件以上選択|選択ノード間のエッジに基づくトポロジカル順（未接続分は `x` 座標 → `y` 座標 → 選択順）でテキストと画像を分離収集します。選択ノード間に循環が含まれる場合は、一部を配置順で補完して警告を表示します。|

## 5. 右クリックメニュー

右クリックした対象によって、表示されるメニュー項目が変わります。`Escape` またはメニュー外クリックで閉じられます。

### 5.1 テキストノードを右クリック

|項目|動作|
|---|---|
|`編集`|テキストノード詳細エディタを開きます。|
|`Markdown 出力`|ノードの本文を `.md` ファイルとしてエクスポートします。|
|`Marp 出力`|このノードと上流チェーンを Marp 形式の Markdown（`.md`）としてエクスポートします。|
|`削除`|このノードを削除します。|

### 5.2 画像ノードを右クリック

|項目|動作|
|---|---|
|`拡大表示`|画像ライトボックスを開きます。|
|`画像出力`|元画像をローカルファイルとしてエクスポートします。|
|`Marp 出力`|このノードと上流チェーンを Marp 形式の Markdown（`.md`）としてエクスポートします。|
|`削除`|このノードを削除します。|

### 5.3 複数選択ノードを右クリック

|項目|動作|
|---|---|
|`Marp 出力（N件）`|選択中のノード群をトポロジカル／配置順で Marp 形式の Markdown としてエクスポートします。|
|`選択ノードを削除`|選択中のノードをまとめて削除します。|

### 5.4 エッジを右クリック

|項目|動作|
|---|---|
|`エッジを削除`|対象のエッジを削除します。|

## 6. AI 生成機能

### 6.1 テキスト生成（`テキスト` モード）

OpenAI 互換 API（`POST {baseURL}/chat/completions`）を使用してテキストを生成します。

1. 必要に応じて参照したいノードを選択します（未選択でも実行できます）。
2. コマンドドックで `テキスト` を選び、指示や質問を入力します。
3. `送信` または `Ctrl+Enter`（macOS は `Command+Enter`）で実行します。
4. 生成が完了すると、選択ノードの右側に新しいテキストノードが作成され、エッジで接続されます。

- **Vision（画像入力）**：収集されたコンテキストに画像ノードが含まれる場合、画像データもマルチモーダル入力として送信されます。Vision 対応モデルを設定してください。
- **ローカル LLM 対応**：設定の `API Key` が空欄の場合、`Authorization` ヘッダーを省略してリクエストするため、認証不要のローカル LLM（Ollama、LocalAI など）にも接続できます。
- **自動サマリー**：テキスト生成後、自動でサマリーが生成されてカード表示に反映されます。サマリー生成に失敗した場合でも本文はそのまま保持され、エラー通知が表示されます。

### 6.2 画像生成（`画像` モード）

4 つのプロバイダー（OpenRouter、OpenAI、Google、xAI）を切り替えて画像を生成・編集できます。

1. 必要に応じて参照したい画像ノードや指示テキストノードを選択します。
2. コマンドドックで `画像` を選び、使用するプロバイダーを選択します。
3. プロンプトを入力し、`送信` または `Ctrl+Enter`（macOS は `Command+Enter`）で実行します。
4. 生成された画像は `画像保存先ディレクトリ` に衝突しないファイル名で保存され、新しい画像ノードが 1 つキャンバスに追加されます。

**参照画像の扱い（プロバイダー別）**：

- **OpenAI**：参照画像がない場合は Images API、参照画像がある場合は Responses API を使用します（最大 5 枚まで参照可能）。
- **xAI**：参照画像がない場合は `/v1/images/generations`、参照画像がある場合は先頭 1 枚を使用して `/v1/images/edits` を呼び出します。
- **OpenRouter / Google**：選択された参照画像をプロンプトと合わせて送信します（対応枚数や編集可否は利用モデルに依存します）。

## 7. ファイルの取り込み・保存・エクスポート

### 7.1 ドラッグ＆ドロップでファイルを取り込む

OS のファイルマネージャからキャンバス上へファイルをドラッグ＆ドロップすると、ドロップ位置にノードが作成されます。

|種類|対応拡張子|取り込み結果|
|---|---|---|
|テキスト|`.txt`, `.md`|内容を読み込み、新規テキストノードとして配置します。|
|画像|`.png`, `.jpg`, `.jpeg`, `.webp`|`画像保存先ディレクトリ/Import/` へ衝突しないファイル名でコピーし、新規画像ノードとして配置します。|

非対応の拡張子や読み込み失敗時はトースト通知でエラーが表示されます。

### 7.2 キャンバスの保存と読み込み

- **保存**：上部バーの `保存` から任意の `.json` ファイル（version `1.1`）へ保存します。ノード、エッジ、配置、サイズ、および安全なメタデータが含まれます（API キー等の秘匿情報は保存されません）。
- **読み込み**：上部バーの `開く` から `.json` ファイルを読み込みます。既存の `v1.0` / `v1.1` 形式の Canvas JSON と互換性があります。

未保存の編集内容はアプリ終了時に失われるため、必要な作業は明示的に保存してください。

### 7.3 単体エクスポート

- **テキストノード**：右クリックメニューの `Markdown 出力`、または詳細エディタの `Markdown 出力` から `.md` ファイルとして保存します。
- **画像ノード**：右クリックメニューの `画像出力`、またはライトボックスの `画像をエクスポート` から元の画像形式で保存します。

### 7.4 Marp スライドとしてエクスポート

ノードを右クリックして `Marp 出力`（複数選択時は `Marp 出力（N件）`）を選びます。

- 単一ノードから実行した場合はそのノードと上流チェーン、複数選択から実行した場合は選択ノード群をトポロジカル／配置順で並べます。
- 先頭に Marp フロントマター（`marp: true`, `paginate: true`）が付与され、各ノードが `---` で区切られます。
- テキストノードは本文、画像ノードは `![bg contain](file://...)` 記法で埋め込まれます（画像ファイルが見つからない場合はフォールバックコメントが出力されます）。

## 8. 設定

上部バーの `設定` をクリックして設定モーダルを開き、変更後に右下の `保存` を押します（`キャンセル` または `Escape` で破棄して閉じます）。

### 8.1 `LLM 設定` タブ

|項目|内容|
|---|---|
|`Base URL`|OpenAI 互換の API エンドポイント（例：`https://api.openai.com/v1`、`http://localhost:11434/v1`）。|
|`Model`|テキスト生成・サマリー生成に使うモデル名。画像入力を使う場合は Vision 対応モデルを指定します。|
|`API Key`|プロバイダーの API キー。右端のアイコンで表示／非表示を切り替えられます。ローカル LLM の場合は空欄可。|
|`System Prompt`|すべてのテキスト生成に適用する共通指示。空欄時は既定のシステムプロンプトを使用します。|
|`サマリー最大文字数目安`|自動サマリー生成時の目安文字数（`10`〜`2000`、既定値 `100`）。|

### 8.2 `画像生成` タブ

|項目|内容|
|---|---|
|`デフォルトプロバイダー`|起動時および既定で使用する画像生成プロバイダー（`OpenRouter` / `OpenAI` / `Google` / `xAI`）。|
|`画像保存先ディレクトリ`|生成画像およびインポート画像の保存先。相対パスの既定値は `Image/` です。|
|`プロバイダー別設定`|4 プロバイダーそれぞれの設定をタブで切り替えて編集します。全プロバイダーの設定が個別に保持されるため、デフォルトを切り替えても他プロバイダーのキーやモデルは失われません。|

各プロバイダーの設定項目と既定値：

|プロバイダー|Base URL（既定値）|Model（既定値）|API Key|
|---|---|---|---|
|`OpenRouter`|`https://openrouter.ai/api/v1`|`sourceful/riverflow-v2-fast`|必要|
|`OpenAI`|`https://api.openai.com/v1`|`gpt-image-1.5`|必要|
|`Google`|（固定エンドポイント）|`gemini-2.5-flash-image`|必要|
|`xAI`|（固定エンドポイント）|`grok-imagine-image`|必要|

### 8.3 `キャンバス管理` タブ

- **`キャンバスを初期化（Clear Canvas）`**：確認ダイアログで確定すると、現在のキャンバス上のすべてのノード・エッジ・選択状態・編集中内容を消去します。この操作は取り消せません。ディスク上に保存済みの画像ファイル自体は削除されません。

## 9. 保存データとセキュリティ

### 9.1 アプリ設定（`config.json`）

OS ごとに次の場所へ保存されます。

- **Windows**：`%APPDATA%\fm-doc-canvas\config.json`
- **macOS**：`~/Library/Application Support/fm-doc-canvas/config.json`
- **Linux**：`~/.config/fm-doc-canvas/config.json`

旧バージョンのフラット形式（`imageGen.baseURL` / `model` / `apiKey`）で保存された `config.json` は、読み込み時にプロバイダー別構造へ自動マイグレーションされます。

> **セキュリティ注意**：API キーはローカルの `config.json` のみに平文で保存され、Canvas JSON・ログ・エラーメッセージには出力されません。`config.json` を公開リポジトリや第三者へ共有しないようご注意ください。

### 9.2 Canvas データ

`保存` でユーザーが選択した任意の `.json` ファイルに保存されます。秘匿情報は含まれません。

### 9.3 画像ファイルとパス検証

生成画像は `画像保存先ディレクトリ`（既定 `Image/`）、ドラッグ＆ドロップで取り込んだ画像は配下の `Import/` に保存されます。画像の読み込み・エクスポート時にはパストラバーサル（`..`、絶対パス、保存先ディレクトリ外への参照）が拒否されます。

Canvas JSON を別 PC へ移動する場合は、対応する画像保存先ディレクトリも合わせて移動してください。

## 11. よくある問題

### 送信ボタンが押せない

- プロンプト入力欄が空でないか確認してください。
- 別の生成処理が実行中（`生成中` 表示）でないか確認してください。

### テキスト生成や画像生成でエラーになる

- 設定モーダルの `Base URL`、`Model`、`API Key` を確認してください。
- `画像` モードでは、コマンドドックで選択中のプロバイダーに対して API キーとモデルが設定されているか確認してください。
- 画像ノードをコンテキストに含めてテキスト生成する場合は、Vision 対応の LLM モデルを指定してください。

### ノード同士をエッジで接続できない

- すでに同じ向きのエッジが存在する場合や、接続すると循環（ループ）が発生する場合は接続が拒否されます。エッジの向きや構成を確認してください。

### コンテキストストリップに警告が表示される

- 1 ノード選択時に上流で入力エッジが 2 本以上合流している場合、または既存データに循環が含まれる場合は、意図しない順序混在を防ぐため手前までで上流探索を停止します。複数のブランチをまとめて渡したい場合は、対象ノードを `Shift` + クリックまたは矩形選択で複数選択してください。

### Canvas を開いたら画像が表示されない

- Canvas JSON には画像ファイル本体は埋め込まれません。元の `画像保存先ディレクトリ` と配下の `Import/` フォルダーが存在し、設定の `画像保存先ディレクトリ` が正しく指定されているか確認してください。

## 12. 基本ワークフロー例

### 複数のメモから構成案をまとめ、Marp スライドにする

1. 上部バーの `+ メモ` でメモを追加するか、`.txt` / `.md` ファイルをキャンバスへドロップします。
2. 関連するノード同士を左→右のエッジで繋ぎます。
3. 末尾のノードを選択し、コマンドドックの `テキスト` モードで「これまでの内容をスライド構成案に整理して」と送信します。
4. 生成されたテキストノードをダブルクリックし、詳細エディタの `編集` / `プレビュー` で内容を仕上げます。
5. スライドに含めたいノード群を複数選択（または末尾ノードを単一選択）し、右クリック → `Marp 出力` で `.md` ファイルを保存します。

### 参考画像とテキスト指示から画像バリエーションを作る

1. `.png`、`.jpg`、`.jpeg`、または `.webp` ファイルをキャンバスへドロップします。
2. 必要に応じて変更方針を書いたテキストノードを追加し、参考画像ノードと合わせて選択します。
3. コマンドドックで `画像` モードに切り替え、プロバイダーを選んでプロンプトを送信します。
4. 生成された画像ノードをダブルクリックしてライトボックスで確認し、元プロンプトを微調整したい場合は `入力欄へ追記` を押して再生成します。
5. 完成した画像を右クリック → `画像出力`（またはライトボックスの `画像をエクスポート`）で保存します。
