# FM Doc Canvas リファレンスマニュアル

[日本語](reference.md) | [English](reference_en.md)

この文書は、FM Doc Canvas の GUI から利用できる機能をまとめた操作リファレンスです。2026-08-19 時点の日本語 GUI と実装に基づいています。

> **表記について** 画面上では `Canvas`、`Relation`、`SubCanvas`、`Chat`、`Direct` などの名称が英語のまま表示されます。本書でも GUI の表記に合わせます。

## 1. アプリの目的

FM Doc Canvas は、テキスト、Markdown アーティファクト、画像を無限 Canvas 上に配置し、Relation で関連付けながら思考や資料を整理するデスクトップアプリです。LLM、画像生成、Web 検索を利用して、Canvas 上の情報を要約・比較・発展させることもできます。

Canvas は一時的なワークベンチとして使い、完成したテキスト、画像、スライド原稿を個別にエクスポートできます。

## 2. 画面構成

### 2.1 上部ツールバー

|項目|動作|
|---|---|
|`テキスト`|空の Text ノードを追加します。|
|`アーティファクト`|空の Artifact ノードを追加します。|
|`元に戻す`|直前の Canvas 操作を取り消します。|
|`自動配置`|現在の Canvas のノードを自動整列します。|
|`AI アシスタント`|画面右側の AI アシスタントを開閉します。|
|`設定`|画面右側の設定ドロワーを開きます。|

### 2.2 パンくずリスト

ツールバーの下に、現在位置が `Workspace > SubCanvas 名` の形式で表示されます。

- `親`：1 階層上の Canvas に戻ります。Workspace 直下では無効です。
- Canvas 名：選択した階層へ移動します。
- 上位境界 Relation がある場合は、その件数も表示されます。

### 2.3 メイン Canvas

ノードを配置、選択、移動、接続する作業領域です。

- 空白部分をドラッグ：Canvas を移動します。
- マウスホイール：拡大・縮小します。
- 左下の `+` / `-`：拡大・縮小します。
- 左下の Fit View：すべてのノードが見える表示に調整します。
- 左下のロック：Canvas の操作可否を切り替えます。
- 右下の Mini Map：Canvas 全体に対する現在位置を表示します。

### 2.4 ノードエディター

Text または Artifact ノードを選択すると画面左側に表示されます。`×` で閉じられます。

|項目|動作|
|---|---|
|`編集`|Markdown ソースを編集します。変更内容はノードへ即時反映されます。|
|`プレビュー`|Markdown のレンダリング結果を表示します。|
|`アーティファクトとして` / `テキストとして`|Text と Artifact の役割を相互変換します。|
|ファイル名|Artifact のエクスポート時に使うファイル名です。|
|`要約`|ノードに表示する短い説明です。直接編集できます。|
|`再生成`|LLM で要約を生成し直します。LLM 設定が必要です。|

Text／Artifact ノードをダブルクリックしてエディターを開くこともできます。

### 2.5 AI アシスタント

`AI アシスタント` を押すと画面右側に表示されます。左端をドラッグすると幅を変更できます。詳しくは「7. AI アシスタント」を参照してください。

### 2.6 設定ドロワー

`設定` を押すと画面右側に表示されます。LLM、画像生成、Web 検索、保存／読込などを設定します。設定項目は「10. 設定」を参照してください。

## 3. ノードの種類

### 3.1 Text

メモ、AI の回答、調査途中の情報などを保持する Markdown テキストです。Artifact と相互変換できます。

### 3.2 Artifact

ファイルとして完成させ、Markdown でエクスポートすることを想定したテキストです。Text と同じく Markdown 編集とプレビューに対応します。

### 3.3 Image

ファイルから取り込んだ画像、または AI が生成した画像です。

- ダブルクリック：拡大表示します。
- 生成画像には、生成時のプロンプト、プロバイダー、モデルなどの情報が保持されます。
- 画像ノードも Chat／Direct のコンテキストとして選択できます。画像入力対応モデルを設定してください。

### 3.4 FolderNode

SubCanvas の入口を表すノードです。ダブルクリックすると、その SubCanvas へ移動します。

## 4. 選択と基本操作

### 4.1 ノードの選択

- クリック：1 ノードを選択します。
- `Ctrl`、`Command`、または `Shift` を押しながらクリック：複数選択します。
- 空白部分をクリック：選択を解除し、ノードエディターを閉じます。

複数選択は、比較、Relation 作成、SubCanvas 作成、Marp エクスポートなどで使用します。

### 4.2 ノードの移動

ノードをドラッグして任意の位置へ移動します。`自動配置` を使うと現在の Canvas 内を自動整列できます。

### 4.3 Relation の簡易作成

ノードの接続ハンドルから別ノードの接続ハンドルへドラッグすると Relation を作成できます。種別、理由、方向を明示したい場合は右クリックメニューの `Relation を追加` を使用します。

### 4.4 元に戻す

`元に戻す` は、ノード／Relation の作成・編集・削除、Direct Transform、SubCanvas 変換などの直前操作を取り消します。AI 操作の完了通知に専用の `元に戻す` が表示される場合もあります。

## 5. 右クリックメニュー

表示される項目は、右クリックした場所、ノード種別、選択数、現在の Canvas 階層によって変わります。

### 5.1 ノードを右クリック

|項目|動作・条件|
|---|---|
|`SubCanvas を作成`|選択ノードを新しい SubCanvas へ移動し、現在の Canvas に FolderNode を作成します。|
|`選択したノードを親 Canvas へ移動`|SubCanvas 内の選択ノードを 1 階層上へ移動します。|
|`SubCanvas の名前を変更`|FolderNode が示す SubCanvas の名前を変更します。|
|`SubCanvas を削除`|SubCanvas を解消します。メンバーは親 Canvas へ戻り、メンバー間 Relation は保持されます。|
|`要約`|選択内容を LLM で要約し、派生 Text ノードを作成します。|
|`比較`|選択した複数ノードを比較し、派生 Text ノードを作成します。|
|`反対意見`|選択内容に対する反対意見を生成し、派生 Text ノードを作成します。|
|`Web を検索`|選択内容を検索 query として Web 検索します。|
|`Relation を追加`|選択ノード間の Relation を Relation エディターで作成します。|
|`Relation を提案`|LLM が Relation の候補を提示します。確認後に適用します。|
|`エクスポート`|Text／Artifact は `.md`、Image は画像ファイルとして保存します。|
|`スライドとしてエクスポート (Marp)`|選択した Text／Artifact を Marp 形式の Markdown にまとめます。右クリックしたノードが未選択なら対象へ追加されます。|
|`ノードを削除`|対象ノードを削除します。|

### 5.2 Relation を右クリック

- `Relation を編集`：ソース、ターゲット、種別、方向、理由を変更します。
- `方向を反転`：Relation の向きを入れ替えます。
- `Relation を削除`：Relation を削除します。

### 5.3 Canvas の空白部分を右クリック

- `Relation を提案`：現在の対象範囲から Relation 候補を生成します。
- `Cluster を提案`：関連するノードのまとまりを Generated View として提案します。

## 6. Relation と SubCanvas

### 6.1 Relation エディター

`Relation を追加` または `Relation を編集` で開きます。

|項目|内容|
|---|---|
|`ソースノード`|Relation の起点です。|
|`ターゲットノード`|Relation の終点です。ソースと同じノードは指定できません。|
|`種別`|`source`、`derived`、`supports`、`opposes`、`similar` から選択します。|
|`方向`|順方向（ソース → ターゲット）または逆方向を選びます。|
|`理由`|Relation の根拠や説明を記録します。|

### 6.2 SubCanvas を作成する

1. 同じ Canvas 上で、まとめたいノードを 1 件以上選択します。
2. 選択ノードを右クリックし、`SubCanvas を作成` を選びます。
3. 作成された FolderNode をダブルクリックして SubCanvas に入ります。
4. `親` またはパンくずリストで上位 Canvas に戻ります。

SubCanvas 内では、選択ノードを右クリックして親 Canvas へ戻せます。

### 6.3 SubCanvas を削除する

FolderNode を右クリックして `SubCanvas を削除` を選び、確認ダイアログで確定します。

- SubCanvas のメンバーは親 Canvas へ移動します。
- メンバー間の Relation は保持されます。
- FolderNode に接続していた Relation は削除されます。
- `元に戻す` で復元できます。

## 7. AI アシスタント

AI アシスタント上部の `Chat` と `Direct` で動作を切り替えます。選択ノードはコンテキストとして渡され、`Context` 欄に Text／Image の件数が表示されます。

### 7.1 Chat モード

LLM と継続的に会話するモードです。

1. 必要に応じて Canvas 上のノードを選択します。
2. `AI アシスタント` を開き、`Chat` を選びます。
3. 入力欄へ質問や指示を入力します。
4. `送信` または `Ctrl+Enter`（macOS は `Command+Enter`）で実行します。
5. 実行中は `停止` で中断できます。

上部のセッション選択で過去の会話を切り替え、`新規` で新しい会話を作成します。会話内で Canvas 変更が提案された場合は、提案カードの内容を確認して適用または拒否します。提案は自動適用されません。

### 7.2 Direct モード

会話履歴を介さず、選択した Canvas 情報へ直接処理を行うモードです。

- `Text`：プロンプトとコンテキストからテキストを生成し、新しい Text ノードを作成します。
- `Image`：プロンプト、選択画像、選択テキストを使って画像を生成または編集し、新しい Image ノードを作成します。
- `画像プロバイダー`：その実行で使う OpenRouter、OpenAI、Google、xAI を選択します。

入力後、`生成` を押します。完了すると結果、作成ノード ID、または差分が表示されます。Direct 操作の結果通知から `元に戻す` を実行できます。

### 7.3 次の一手

`次の一手` は、現在の選択、Canvas、会話から次に実行できる操作を提案します。提案例は比較、反対意見、Web 検索、Relation 提案、Cluster 提案、確認質問です。

提案の対象ノードや query を確認・編集してから実行してください。古い選択や Canvas に対する提案は無効になる場合があります。

## 8. Web 検索

Web 検索は、AI アシスタントの入力欄に query を入力して `Web検索` を押すか、ノードの右クリックメニューから開始します。

1. 設定で Web 検索プロバイダーと API キーを設定します。
2. query を入力して検索を実行します。
3. 画面上部の Projected Context で、検索結果の Sources、Claims、Relation 候補を確認します。
4. Canvas に残したい Source／Claim と Relation をチェックします。
5. `Canvas に追加` を押して昇格します。

検索結果は確認用の一時データです。必要な項目を選択して追加するまで、Canvas の永続ノードにはなりません。URL は `URL を開く` から外部ブラウザーで確認できます。

## 9. Relation／Cluster の AI 提案

### 9.1 Relation 提案

`Relation を提案` を実行すると候補一覧が表示されます。候補のソース、ターゲット、種別、理由を確認し、必要に応じて編集してから承認します。拒否または閉じることもできます。

### 9.2 Cluster 提案と Generated View

`Cluster を提案` を実行すると、ノードを色分けした一時的な Generated View が提案されます。承認すると、上部に View バナーと Cluster チップが表示されます。

- Cluster 名をクリック：名前を変更します。
- `×`：その Cluster を一時 View から除外します。
- `SubCanvas に変換`：Cluster のメンバーを実体のある SubCanvas へ移動します。
- `View を閉じる`：一時表示を終了します。元の Canvas 文書は変更しません。

Generated View 自体は一時的な表示です。`SubCanvas に変換` を確定したときだけ Canvas 文書が変更されます。

## 10. 設定

設定を変更したら、ドロワー下部の `設定を保存` を押します。

### 10.1 言語

- `システム設定に従う`
- `日本語`
- `English`

切り替えると、主要な GUI、メッセージ、ダイアログが選択言語で表示されます。

### 10.2 ファイル操作

- `Canvas を保存`：現在の Workspace を `.json` ファイルに保存します。
- `Canvas を開く`：保存済み `.json` ファイルを読み込みます。

未保存の編集内容はアプリ終了時に失われるため、必要な作業は明示的に保存してください。

### 10.3 LLM 設定

|項目|内容|
|---|---|
|`API ベース URL`|OpenAI 互換の API エンドポイントです。|
|`モデル`|テキスト生成、要約、Chat に使うモデル名です。|
|`API キー`|LLM プロバイダーの API キーです。|
|`システムプロンプト`|応答言語、書式、方針などの共通指示です。|

画像ノードをコンテキストに含める場合は、画像入力に対応したモデルを指定してください。

### 10.4 画像生成

|項目|内容|
|---|---|
|`プロバイダー`|OpenRouter、OpenAI、Google、xAI から選択します。|
|`モデル`|選択プロバイダーで使う画像生成モデル名です。|
|`API キー`|選択プロバイダーの API キーです。|
|`ダウンロード先`|生成画像とインポート画像の保存先です。相対パスの既定値は `Image/` です。|

複数画像を参照する編集機能は、利用するプロバイダー／モデル側の対応状況にも依存します。

### 10.5 Web 検索

- `プロバイダー`：Ollama、Kagi、Brave から選択します。
- `API キー`：Kagi／Brave など、選択プロバイダーで必要な認証情報を入力します。

### 10.6 生成設定

`要約の最大文字数` で、ノード要約の最大長を設定します。

### 10.7 危険な操作

- `Canvas をクリア`：現在の Canvas のノードと Relation を削除します。`元に戻す` で復元できます。
- `新しいワークスペース`：新しい Workspace を開始し、現在の会話もクリアします。

## 11. ファイルの取り込みとエクスポート

### 11.1 ファイルを Canvas へ取り込む

対応ファイルを OS から Canvas 上へドラッグ＆ドロップします。ドロップ位置にノードが作成されます。

|種類|対応拡張子|取り込み結果|
|---|---|---|
|テキスト|`.txt`, `.md`|Artifact ノードとして追加します。元のファイル名を保持します。|
|画像|`.png`, `.jpg`, `.jpeg`, `.webp`|Image ノードとして追加し、画像保存先の `Import/` 配下へコピーします。|

未対応形式、読込失敗、コピー失敗の場合は Canvas 下部にエラーが表示されます。

### 11.2 ノードをエクスポートする

ノードを右クリックして `エクスポート` を選びます。

- Text：要約または設定された名前を候補にした `.md` ファイル。
- Artifact：ノードのファイル名を候補にした `.md` ファイル。
- Image：元の画像形式で保存。

### 11.3 Marp スライドをエクスポートする

複数の Text／Artifact を選択し、右クリックから `スライドとしてエクスポート (Marp)` を選びます。各ノードが `---` で区切られた Marp Markdown として保存されます。Image ノードは Marp 本文には追加されません。

## 12. 保存データとセキュリティ

### 12.1 Canvas データ

`Canvas を保存` でユーザーが選んだ任意の `.json` ファイルに保存されます。ノード、Relation、Canvas 階層、配置などが含まれます。

### 12.2 アプリ設定

Windows では通常、次の場所へ保存されます。

```text
%APPDATA%\fm-doc-canvas\config.json
```

API キーはローカル設定ファイルに保存されます。設定ファイル、Canvas ファイル、ログを公開リポジトリや第三者へ不用意に共有しないでください。

### 12.3 Chat 履歴

Windows では通常、次の場所へ Canvas ID ごとに保存されます。

```text
%APPDATA%\fm-doc-canvas\chat-sessions.json
```

Canvas ファイルを別名保存しても、Chat 履歴は安定した Canvas ID を基準に管理されます。`新しいワークスペース` は現在の会話をクリアします。

### 12.4 画像ファイル

生成画像は設定した `ダウンロード先` に保存されます。取り込んだ画像は、その配下の `Import/` にコピーされます。Canvas JSON だけを別 PC へ移動すると画像を参照できない場合があるため、画像フォルダーも合わせて管理してください。

## 13. キーボードとアクセシビリティ

|操作|キー|
|---|---|
|Chat／Direct の実行|`Ctrl+Enter`。macOS は `Command+Enter`。|
|複数選択|`Ctrl`、`Command`、または `Shift` を押しながらノードをクリック。|
|メニュー／ダイアログを閉じる|`Escape`。|
|右クリックメニュー内の移動|`↑`、`↓`、`Home`、`End`、`Tab`、`Shift+Tab`。|
|ダイアログ内の移動|`Tab`、`Shift+Tab`。|
|Cluster 名の確定|`Enter`。|

## 14. よくある問題

### AI 操作ボタンが無効になっている

- 入力欄が空でないか確認します。
- 設定の API ベース URL、モデル、API キーを確認します。
- 別の AI／Web 検索処理が実行中でないか確認します。
- Chat 履歴の読み込み完了を待ちます。

### 画像を AI に渡せない

- 画像ノードを選択した状態で AI アシスタントを開きます。
- `Context` の Image 件数を確認します。
- 画像入力対応の LLM／画像モデルを使用します。
- 画像ファイルが設定した画像保存先に存在するか確認します。

### Web 検索に失敗する

- Web 検索プロバイダーと API キーを確認します。
- query が空でないか確認します。
- Projected Context のエラー表示から `設定を開く` を選んで再設定します。

### 提案を適用できない／無効と表示される

AI 処理中にノード、Relation、Canvas、選択状態が変わると、古い結果の誤適用を防ぐため提案が stale（無効）になることがあります。現在の対象を選び直して再実行してください。

### Canvas を開いたら画像が表示されない

Canvas JSON は画像本体を常に内包するわけではありません。元の画像保存先と `Import/` フォルダーを復元し、設定の `ダウンロード先` が正しいことを確認してください。

## 15. 基本ワークフロー例

### 調査結果を Artifact にまとめる

1. 設定で LLM と Web 検索を構成します。
2. Text ノードへ論点や検索語を記入します。
3. ノードを選び、`Web を検索` を実行します。
4. Projected Context で必要な Sources／Claims を選び、Canvas に追加します。
5. 関連ノードを複数選択し、`要約` または `比較` を実行します。
6. 結果ノードを Artifact に変換し、編集／プレビューで仕上げます。
7. 右クリックの `エクスポート` で Markdown を保存します。

### 参考画像から画像バリエーションを作る

1. `.png`、`.jpg`、`.jpeg`、`.webp` を Canvas へドロップします。
2. 参考にする Image ノードと、必要なら指示を書いた Text ノードを選択します。
3. AI アシスタントで `Direct` → `Image` を選びます。
4. 変更内容を入力し、画像プロバイダーを選んで `生成` を押します。
5. 新しい Image ノードを確認し、必要なら `元に戻す` または再生成します。
6. 完成画像を右クリックしてエクスポートします。
