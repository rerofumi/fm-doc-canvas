# Review Notes

## Review Findings

- 現状の画像生成フローでは、画像ノードとは別にプロンプト説明用テキストノードを作成している。
- 画像ノード自体に `alt` としてプロンプトを保持しているため、表示用データは既存の生成フローから追加しやすい。
- テキスト生成ノードには現在、質問プロンプトを保持していないため `originalPrompt` を追加する必要がある。
- キャンバスのズーム範囲は `CanvasArea.tsx` の `ReactFlow` に `minZoom` / `maxZoom` を渡すことで対応できる。
- Rubberduck により、長文プロンプトの省略方針、既存プロンプト専用ノードの扱い、全文確認 UI の有無、React Flow ズームコントロールの動作確認、新旧バージョン互換性、共通コンポーネント化余地が指摘された。
- Advisor により、基本方針は「案 1: 仕様どおり MVP 実装」で妥当との助言を得た。必要最小限の共通化、既存プロンプト専用ノードの非移行、長文全文確認の `title` 属性暫定対応が推奨された。

## Advisor Review Findings

- 推奨案: `案 1: 仕様どおり MVP 実装`。
- 画像生成プロンプトは別ノードではなく、画像ノードのカード下に表示する方針で妥当。
- テキスト生成回答ノードに元の質問プロンプトをカード下表示する方針で妥当。
- ズーム範囲は `minZoom=0.1` / `maxZoom=4.0` に広げる方針で妥当。
- `CustomNode` / `ImageNode` の表示部分は、必要なら軽量な表示関数または小さな `PromptCaption` 程度に最小共通化する。
- 大きな `PromptCaption` 基盤、展開 UI、コピー、モーダル、ドロワは MVP に入れない。
- 既存の古いプロンプト専用ノードは移行・削除せず、通常のテキストノードとして残す。
- 長文全文確認は MVP では 3 行省略 + `title` 属性で暫定対応する。
- `fitView` と `minZoom=0.1` の相互作用は実機確認する。

## Fixed Items

- 画像生成時にプロンプトノードを追加しない方針を確定。
- 生成プロンプトはノード data の任意項目として保持する方針を確定。
- 保存 JSON のバージョン番号は変更しない方針を確定。

## Deferred Items

- プロンプト表示のラベル文言（`Prompt` / `質問` / `生成プロンプト`）は仮に `Prompt` とする。
- 表示行数は仮に 3 行上限とする。
- 長文プロンプトの全文確認 UI は MVP では導入せず、将来候補とする。
- 既存の古いプロンプト専用テキストノードの整理は、今回の MVP では自動処理しない。

## Rejected Options

- 画像生成プロンプトを別ノードとして残す案: キャンバスを不要に増やすため却下。
- 保存 JSON のバージョンを上げる案: 任意項目の追加で既存データと互換性があるため却下。
- バックエンド API を変更する案: 本改善はフロントエンド表示・生成ノード data のみで完結するため却下。

## Current Non-Goals

- 画像生成 API の変更
- 既存ノードの自動マイグレーション
- ズーム範囲のユーザー設定化
- プロンプト表示文言の多言語化

## Future Plans

- プロンプト表示のラベル・行数・折りたたみ挙動を UX 確認後に調整する。
- 必要に応じてズーム範囲をユーザー設定化する。
- 生成元プロンプトの履歴表示や編集機能を検討する。
- 長文プロンプトの全文確認 UI（ツールチップ・詳細表示など）を検討する。
- `CustomNode` / `ImageNode` のカード下表示を共通コンポーネント化する余地を検討する。

## Next Plan Candidates

- キャンバスズーム設定の UI 追加
- 生成元プロンプトの編集・再表示機能
