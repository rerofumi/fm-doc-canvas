# Requirements

## Scope

本要求はフロントエンドの表示・生成フロー改善に限定する。バックエンド、画像生成 API、保存形式の互換性破壊は含めない。

## Functional Requirements

### FR-1 画像生成時のプロンプトノード作成停止

- 画像生成モードで生成が完了した場合、画像ノードのみを追加すること。
- 画像生成プロンプトを説明するテキストノードを新規追加しないこと。

### FR-2 画像カード下の簡易プロンプト表示

- 画像生成時に使用したプロンプトを画像ノードのデータとして保持すること。
- 画像ノードのカード下に、生成プロンプトを簡易表示すること。
- 生成プロンプトを持たない画像ノード（例: インポート画像）では表示しないこと。

### FR-3 テキスト回答ノード下の元の質問プロンプト表示

- テキスト生成時にユーザーが入力した質問プロンプトを、生成されたテキストノードのデータとして保持すること。
- テキストノードのカード下に、元の質問プロンプトを簡易表示すること。
- 元の質問プロンプトを持たない既存ノードや空ノードでは表示しないこと。

### FR-4 キャンバスズーム範囲の拡張

- キャンバスの縮小側・拡大側の上限を、現在より 2 段階以上広げること。
- React Flow のズーム操作が新しい範囲を尊重すること。

## Non-Functional Requirements

- 既存のキャンバス JSON を壊さないこと。
- 既存ノードの表示を、プロンプト非保持時は可能な限り変更しないこと。
- 生成プロンプトは編集本文やサマリーとは独立して扱うこと。
- UI 表示は長文でもカードを過度に大きくしないこと。

## Constraints

- Frontend 内の変更に留める。
- `@xyflow/react` の既存 Zoom 制御を使用する。
- AGENTS.md に従い、開発コマンドは `mise` を経由して実行する。

## Compatibility

- `TextNodeData.originalPrompt?: string`
- `ImageNodeData.prompt?: string`

のように任意項目として追加し、既存データとの読み込み互換性を保つ。

## Out of Scope

- バックエンドの画像生成 API 変更
- 保存 JSON のバージョン番号変更
- 既存ノードの自動マイグレーション
- ユーザー設定によるズーム範囲変更
- プロンプト表示文言の多言語化

## Acceptance Criteria

- [ ] 画像生成後に画像ノードが 1 つだけ追加され、プロンプト説明用のテキストノードが追加されない。
- [ ] 画像生成ノードのカード下に生成プロンプトが表示される。
- [ ] インポート画像などプロンプトを持たない画像ノードにはプロンプト表示が出ない。
- [ ] テキスト生成ノードのカード下に元の質問プロンプトが表示される。
- [ ] 空ノードや既存の通常ノードには、`originalPrompt` がない限り表示が出ない。
- [ ] 既存の古いプロンプト専用テキストノードがある場合、今回の改善では通常のテキストノードとして残り、自動削除されない。
- [ ] 長文プロンプトはカードを過度に大きくせず、3 行程度で省略される。
- [ ] 長文プロンプトは `title` 属性などで全文を補助確認できる。
- [ ] キャンバスのズームイン・ズームアウト範囲が現在より広がる。
- [ ] `fitView` と `minZoom=0.1` の組み合わせで初期表示が崩れない。
- [ ] `npm run build` が成功する。
