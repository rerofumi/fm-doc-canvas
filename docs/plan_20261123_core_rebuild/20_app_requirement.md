# App Requirements

## Purpose

**「広いキャンバスに断片を並べ、選んだ文脈でAIに問い、画像を生成して手元に確保する」**という `fm-doc-canvas` 本来の価値に立ち返り、迷わず軽快に使えるデスクトップアプリを新規に構築する。

- **対象者**: ローカル環境でテキスト整理・調査・画像生成を行うデスクトップユーザー（主に個人利用）。
- **達成状態**: 過去の `config.json` と `canvas.json` (v1.0 / v1.1) 資産を活かしたまま、8月改変の複雑なUIに煩わされずに、メモ配置 → 文脈付き LLM 質問 → マルチプロバイダー画像生成・確保 → 保存/エクスポートの一連の作業を完結できること。
- **詳細要求・受け入れ条件の正本**: 機能・制約・確認方法の詳細は [`30_requirement.md`](./30_requirement.md) を参照する。

## Target Environment

- OS: Windows（主対象・実機確認対象）、macOS / Linux でも動作可能な Wails v2 構成。
- Backend: Go (Wails v2)。
- Frontend: React 18, TypeScript, Vite, Zustand, React Flow (`@xyflow/react`), Tailwind CSS。
- Toolchain: `mise.toml` 管理（Go / Node.js / Wails）。コマンドは `mise x -- <command>` または `mise run <task>` で実行する。
- VCS: `jj` (Jujutsu)。

## Design Philosophy（新規UI/UXコンセプト）

過去のUI実装は流用せず、以下の原則で画面設計をゼロから組み立てる。

1. **Canvas-First / Low-Chrome（キャンバスが主役）**
   - 画面の大部分を常にキャンバスとして開放する。
   - 常時表示されるUIは「上部の控えめなフローティングバー」と「下部のフローティングコマンドドック」のみとし、常設サイドバーや多層ドロワーを置かない。
2. **Explicit Context（何がAIに送られるかが一目で分かる）**
   - 選択中のノードや上流リンクから集められたコンテキスト（テキスト件数・参照画像枚数）を、プロンプト入力エリア直上にコンパクトなチップとして可視化する。
   - 分岐やループで上流追跡が止まった場合も、静かに失敗させずその場で理由を明示する。
3. **Direct & Fast Manipulation（少ない手数で完結する操作）**
   - ノード追加、質問、画像生成、プロバイダー切替、プロンプト再利用、インポート/エクスポートを最短手数で行える。
   - テキスト・画像の生成時に余計な補助ノード（プロンプト専用テキストノード等）を増やさず、カード自体に元プロンプトを控えめに保持・表示する。
4. **Progressive Disclosure（必要な時だけ詳細を開く）**
   - 普段はカード上で要約・プレビュー・画像を確認し、全文編集や Markdown プレビューが必要な時だけインスペクターを開く。
   - 画像の細部確認はライトボックス（拡大オーバーレイ）で即座に行い、そのままプロンプト再利用やエクスポートへ繋げる。

## Representative Scenarios（代表操作・前後状態・成功結果）

| # | 利用場面 | 前状態 | 代表的な入力・操作 | 成功時の結果（後状態） |
| --- | --- | --- | --- | --- |
| S-1 | キャンバス整理と取り込み | 空または既存ノードがあるキャンバス | テキストノード追加、ドラッグ移動・リサイズ、左右コネクタ連結、ローカル `.md`/`.png` の D&D、「整頓」ボタン押下、Clear Canvas 実行 | ノード・有向エッジが配置され（ループ接続は拒否・通知）、D&D ファイルがノード化され、整頓で接続関係を保って再配置される。Clear Canvas は確認ダイアログ後に全消去される |
| S-2 | 文脈付き LLM 質問（Text モード） | 1件以上（または0件）のテキスト/画像ノードが存在 | ノードを選択（または未選択）し、コマンドドックでコンテキスト件数を確認後、質問を入力して送信 | 選択ノード＋上流チェーンのテキスト・画像が LLM へ送信され、回答が新規テキストノードとして追加される。自動でサマリーが付与され、カード下部に元プロンプトが表示される |
| S-3 | マルチプロバイダー画像生成（Image モード） | 設定モーダルで複数プロバイダーのキーを保存済み | コマンドドックを `Image` に切替え、リクエスト単位でプロバイダーを選び（任意で参照ノードを選択）、プロンプト送信。生成後に画像カードの元プロンプトをクリック | デフォルト設定を変更せずに選択プロバイダーで画像が生成・ローカル保存され、画像ノードのみ 1 つ追加される。元プロンプトのクリックで既存入力を消さずに末尾へ追記される |
| S-4 | 詳細編集・拡大確認・保存/出力 | テキスト・画像ノードがキャンバス上にある | テキストをダブルクリックして Markdown 編集・別ノード切替、画像をダブルクリックしてライトボックス表示、JSON 保存/再読込、単体 `.md`/画像・Marp 出力 | テキスト編集は別ノード切替時に自動確定され、画像は拡大表示・プロンプト確認・出力できる。保存した JSON を再読込（および既存 v1.0/v1.1 読込）して状態が復元され、API Key は JSON に含まれない |
| S-5 | 設定管理と互換維持 | 既存 `config.json`（旧フラット形式含む）または初回起動 | 設定モーダルで LLM・4プロバイダーの API Key/モデルを編集し、デフォルトプロバイダーを切り替えて保存・再起動 | 全プロバイダーのキーが失われず `config.json` に永続化され、旧形式設定も自動マイグレーションされて読み込める |

## Scope Boundaries（再現・新規設計・対象外）

### 再現するもの（v0.4.2 までの基本機能・互換性）
- フリーキャンバス基本操作（パン、広域ズーム `0.1`〜`4.0`、単一/複数選択、移動、リサイズ、Auto-layout、Clear Canvas）。
- テキストノード（Markdown 編集/プレビュー、サマリー生成、元質問プロンプト表示＆追記）および画像ノード（ローカル画像表示、リサイズ、ライトボックス拡大、生成プロンプト表示＆クリック追記）。
- 有向エッジ連結（ループ防止）と上流コンテキスト自動追跡。
- LLM テキスト生成（OpenAI 互換 API、System Prompt、ローカル LLM 向け API Key 省略、Vision 画像入力、自動サマリー）。
- 画像生成 4 プロバイダー（OpenRouter / OpenAI / Google Gemini / xAI）とリクエスト単位切替、参照画像入力、ローカル自動保存。
- ファイル Drag & Drop インポート（`.txt`, `.md`, `.png`, `.jpg`, `.jpeg`, `.webp`）。
- キャンバス JSON 保存/読み込み（v1.0 / v1.1 互換）およびローカル設定（`config.json` 互換・旧フラット形式マイグレーション）。
- エクスポート（単体 Markdown、単体画像、Marp スライド）。

### 新規に設計し直すもの
- **Canvas-First / Low-Chrome UI**: 上部フローティングバー・下部コマンドドック・スライドインインスペクター・ライトボックス・インアプリトースト通知。
- **v0.4.2 既知課題の解消**: xAI 等の HTTP(S) URL レスポンス保存対応、生成/インポート画像ファイル名の衝突防止、プロバイダー別設定の非破壊永続化、HTTP クライアント差し替え可能なテスト容易構造。

### 対象外（Initial Non-Goals / Future Candidates）
- **対象外（再現しない）**:
  - 2026年8月改変で導入した機能群（ChatDrawer、AI パートナーの自律レベル/Orchestration、Proposal ワークフロー、Generated Views / Cluster View、Web 検索プロバイダー統合）。
  - クラウド同期や複数人リアルタイムコラボレーション。
  - ストリーミングテキスト表示・ストリーミング画像表示（MVP ではリクエスト/レスポンス方式を優先）。
  - キャンバス JSON への API Key 保存。
- **後続候補（Future Candidates・今回対象外）**:
  - 同一プロバイダー内の複数プロファイル（複数 API キー・モデルプリセット）。
  - 画像ノードからのワンクリック再生成・バリエーション生成。
  - テーマ切替（Light / Dark）および UI 多言語化（ja / en）（MVP は日本語固定・単一既定テーマ）。
  - OS キーチェーン等を用いた API Key のセキュアストレージ。
  - 分岐合流グラフにおけるマージ順指定や明示的コンテキスト選択 UI。
