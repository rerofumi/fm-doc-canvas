# Claim

## Purpose

2026年8月の大規模改変（ChatDrawer / Artifact / AI協働型Workspace / Orchestration 等）によって肥大化・複雑化した実装を一旦破棄し、**v0.4.2 までに確立していた「キャンバス上にノードを置いて質問し、画像を生成・確保する」基本機能と各AIプロバイダーへのアクセス**を、クリーンな新規ソースコードとして再構築する。

その第一歩として、新規実装の指針となるプランドキュメント一式を整備する。

## Background

- 本アプリ（`fm-doc-canvas`）は本来、フリーキャンバス上にテキストメモや画像を自由に配置・連結し、選択ノードや上流の文脈をもとに LLM へ質問したり、複数プロバイダーを切り替えて画像を生成・保存したりできる軽量なデスクトップツールであった。
- 2026年8月の一連の改変（`plan_20260810_chat_artifact` 〜 `plan_20260817_ui_i18n`）で、右ドロワーチャット、AIパートナーの役割・自律レベル、Proposal、Cluster View、Web検索等の機能を追加したが、操作面や概念モデルが複雑になり、かえって日常的に使いにくくなった。
- そのため、ソースコードを一度リセット（`recreating_20261123`）し、過去のコードをそのまま流用するのではなく、基本機能とプロバイダー連携を整理した上でゼロベースで作り直す方針とした。

## Problem

- 8月改変後の状態では、本来の「キャンバスで思考し、すぐ質問し、すぐ画像を生成・確保する」軽快さが損なわれている。
- 過去のソースコード（v0.4.2以前）にも、段階的な機能追加に伴う設計上の歪み（設定保存時のフラット化の名残、画像URL保存の未対応パス、UIコンポーネントの結合など）が存在していた。
- 過去のUIをそのまま再現するのではなく、基本機能に最適化された見通しの良いUIを新規に設計し直す必要がある。

## Target Users / Environment

- ローカル環境でテキスト整理・調査・画像生成を行うデスクトップユーザー。
- 動作環境: Wails v2 (Go) + React / TypeScript / Zustand / React Flow (`@xyflow/react`) / Tailwind CSS。
- ツールチェーン: `mise.toml` による Go / Node.js / Wails のバージョン統一（`mise x -- <command>` で実行）。
- バージョン管理: `jj` (Jujutsu)。

## Initial Scope

1. **キャンバスとノードの基本機能**
   - パン・広域ズーム・選択（単一/複数）・ドラッグ移動・リサイズ・自動整頓（Auto-layout）・キャンバス初期化。
   - テキストノード（Markdown編集/プレビュー、サマリー保持・生成、元質問プロンプト表示）。
   - 画像ノード（ローカル画像表示、リサイズ、拡大ビュー、生成プロンプト表示・クリック追記）。
   - ノード間の有向エッジ連結（ループ防止、削除）と上流コンテキスト自動追跡。
2. **AIプロバイダー連携の復活**
   - **LLM（テキスト / Vision）**: OpenAI互換 `/chat/completions`（OpenRouter / OpenAI / Ollama 等、API Key任意、システムプロンプト、画像入力対応）。
   - **画像生成（マルチプロバイダー）**: OpenRouter / OpenAI（Images API & Responses API）/ Google Gemini（`generateContent`）/ xAI（Images Generations & Edits）の4プロバイダー対応。全プロバイダーのAPI Keyを同時保持し、生成リクエスト単位で即時切替可能。
3. **ファイル入出力・互換性**
   - キャンバス JSON（v1.0 / v1.1 互換）の保存・読み込み。
   - ローカル設定ファイル（`os.UserConfigDir()/fm-doc-canvas/config.json`）の互換維持。
   - Drag & Drop によるファイルインポート（`.txt`, `.md`, `.png`, `.jpg`, `.jpeg`, `.webp`）。
   - エクスポート（単体 `.md`、単体画像ファイル、Marp スライド `.md`）。
4. **画面UIの新規検討**
   - 過去のUI実装には引きずられず、キャンバス主役（Canvas-First）・低クロームな新しいUI/UXを設計する。

## Initial Technical Hypotheses

- バックエンドの責務を `ConfigService` / `LLMService` / `ImageGenService`（+ 各プロバイダーアダプタ） / `ImageAssetService` / `FileService` の5つに明確分離すれば、Wails v2 バインディングが極めてシンプルになり、Go 単体テストも書きやすい。
- 既存の `config.json` および `canvas.json` (v1.1) フォーマットとの互換性を保つことで、ユーザーが既に登録している API Key や過去に保存したキャンバス資産をそのまま活かせる。
- フロントエンドは Zustand ストアを「キャンバスデータ」「UI状態」「設定」に整理し、コンテキスト収集・Marp変換などの純粋ロジックを `utils/` に分離することで、UIを後から柔軟に磨ける構造にできる。

## Uncertainties

- 新規UIの具体的なビジュアルテイスト（ライト/ダークテーマ、デフォルトテーマ）やキーボードショートカットの優先度。
- UI言語を日本語ベースにするか、最小限の英語/日本語切替を最初から入れるか（本プランではシンプルさ優先で日本語を基本とし、必要になれば後続で i18n を検討する）。
- 生成画像の保存先デフォルト（実行ファイル相対 `Image/` を維持しつつ、開発時・ビルド時の扱いを確認）。
