- 意図・背景: [`10_claim.md`](./10_claim.md)

- ツールチェーン・VCS 規約: [`AGENTS.md`](../../../AGENTS.md)

## Non-Functional Requirements（非機能要求の扱い）

- **セキュリティ・互換性**: 上記 `REQ-11`, `REQ-13`, `REQ-15` として受け入れ条件に組み込む。
- **テスト容易性（設計前提）**: バックエンドの各プロバイダーおよび LLM サービスはベース URL / `http.Client` を差し替え可能とし、フロントエンドのグラフ探索・コンテキスト結合・Marp 変換・JSON 正規化は UI 非依存の純粋関数として実装する（各 REQ の `E1` 検証を成立させる前提）。
- **性能・リソース等の追加数値目標**: **今回追加要求なし**（応答時間・メモリ上限・同時ノード数などの新規数値目標は設定しない）。

## Verification Scope（検証範囲）

### 1. 自動テスト（`E1`）でカバーする範囲
- **Backend (`mise x -- go test ./...`)**:
  - 正常系: `config.json` 読み書き・4プロバイダー同時保持・旧フラット形式マイグレーション、LLM リクエスト構築（System Prompt / Vision / 空 API Key）、4プロバイダー（OpenRouter / OpenAI Images & Responses / Google / xAI）の参照なし・参照あり・レスポンスデコード（Data URL / base64 / inlineData / HTTP(S) URL）、画像保存ファイル名衝突回避、インポート・エクスポート処理。
  - 異常系・境界値: 不正な HTTP ステータス（4xx/5xx）・空レスポンス・不正 JSON、パストラバーサル（`..`、絶対パス、`downloadPath` 外）、非対応拡張子、xAI 参照画像複数枚時の 1 枚制限、OpenAI 参照画像上限（5枚）、サマリー失敗時のエラー返却。
- **Frontend (`mise x -- npm test` 等)**:
  - 正常系: 上流トラバーサル（0件 / 1件チェーン / 複数選択トポロジカル順）、テキスト/画像分離、循環検出、Dagre レイアウト計算、Marp スライド変換、`canvas.json` v1.0 / v1.1 シリアライズ・正規化（ハンドル補完・欠損フィールド補完）。
  - 異常系・境界値: 直接/間接ループ検出、分岐合流での探索停止と警告返却、API Key 等の秘匿情報がシリアライズ結果に含まれないこと。
- **Build (`mise run build`)**: フロントエンドビルドおよび Wails v2 バイナリ生成の成功。

### 2. 実アプリ操作観測（`E2`）でカバーする範囲
- Windows 環境でビルドまたは `wails dev` 起動したアプリ上で、`20_app_requirement.md` の代表シナリオ `S-1`〜`S-5` および `REQ-02`〜`REQ-14` の UI 操作・状態遷移（パン/ズーム `0.1`〜`4.0`、D&D インポート、ノード編集と切替自動確定、ループ拒否、コンテキストチップ、設定永続化・再起動維持、JSON 保存/読込、エクスポート、ローディング中多重送信防止、トースト通知）を観測する。

### 3. 実外部課金 API を伴う確認（`REQ-07`, `REQ-08` の `E2` / `EX` 運用条件）
- **直接確認できない理由**: OpenRouter / OpenAI / Google Gemini / xAI 等の実外部 API 呼び出しには有効な API Key と実課金・外部ネットワーク到達性が必要であり、自動テスト環境やキー未提供環境では全プロバイダーを実課金実行できない。
- **代替確認**:
  1. 全 4 プロバイダーおよび LLM について、`httptest.Server` モックを用いた自動テスト（`E1`）でリクエスト形式・ヘッダー・参照画像・レスポンス解析・エラー処理を検証する。
  2. 実アプリ（`E2`）では、ローカルモックエンドポイント（または利用者が提供する有効 API Key / ローカル LLM）を用いて UI → バックエンド → 保存・ノード追加の一連フローを実観測する。
- **残るリスク**: 外部プロバイダー側の API 仕様変更、モデル ID 廃止（404）、実認証エラー、レート制限はモックでは検知できない。
- **EX 判定条件**: 実キーによる実通信が未実施のプロバイダーについて、上記代替確認（`E1` ＋ ローカルモック `E2`）がすべて `pass` であり、残るリスクを明示した上で利用者（または指定判断者）が承認した場合に `EX` として受け入れ可能とする。

### 4. 検証対象外
- 性能ベンチマーク・大量ノード（数千件等）の負荷試験。
- macOS / Linux 実機での GUI 動作確認（Windows を主対象とし、クロスプラットフォーム互換は標準 API 利用の構造確認 `E3` まで）。
- `20_app_requirement.md` の Non-Goals / Future Candidates に挙げた機能（8月改変機能群、ストリーミング、多言語切替、テーマ切替等）。

## Constraints & Out of Scope（適用制約・対象外）

1. **ツールチェーン制約（`AGENTS.md`）**: `go`, `npm`, `wails` 等は原則直接実行せず、`mise x -- <command>` または `mise run <task>` を経由する。
2. **バージョン管理制約（`AGENTS.md`）**: リポジトリ管理は `jj` を使用する。
3. **データ互換性制約**: 既存 `os.UserConfigDir()/fm-doc-canvas/config.json`（旧フラット形式含む）および既存 `canvas.json`（v1.0 / v1.1）を破壊せず読み込めること。
4. **再構築方針制約**: 過去のソースコードをコピー＆ペーストして復旧せず、ゼロベースでクリーンなコードと新規 Canvas-First UI を構築すること。
5. **対象外**: 2026年8月改変機能群（ChatDrawer / AI パートナー自律レベル / Proposal / Cluster View / Web 検索等）および `20_app_requirement.md` の Non-Goals は一切実装しない。

## Open Items & Design Delegations（未決事項と設計委譲）

- **利用者の判断が必要な矛盾・未決（B）**: **なし**（目的・範囲・維持条件を変える矛盾は確認されなかった）。
- **調査・観測で解ける項目（A）**:
  - 開発環境における `mise` ツールチェーン導入状態と Wails v2 ビルド前提の確認（`REQ-01` 実施時に確認）。
  - 開発時（`wails dev`）とビルド後実行ファイルにおける相対パス `Image/` の解決基準（`architect` が設計で定義し、実装時に観測）。
- **通常の設計範囲として `architect` へ委譲する既定方針**（最終レビュー時に `60_review_packet.md` で利用者に共有）:
  - ビジュアルテーマ: ニュートラルなライトテーマを既定とし、将来切替しやすいトークン構成にする。
  - UI 言語: MVP はシンプルな日本語 UI 固定とする。
  - Auto-layout 方向: 左右コネクタと整合する左→右（`LR`）を既定とする。
