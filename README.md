# fm-doc-canvas

[日本語](README.md) | [English](README_en.md)

`fm-doc-canvas` は、無限キャンバス上にテキストや画像を配置・連結し、LLM（大規模言語モデル）や画像生成 API を活用して思考の整理や拡張を行うデスクトップツールです。

キャンバス上に断片的なメモや画像を並べ、選択したノードと上流のつながりからコンテキストを収集して AI に問いかけたり、複数のプロバイダーを切り替えて画像を生成・保存したりできます。

![日本語でプロダクト設計を検討しているキャンバスのデモ](manuals/screenshot_readme_product_planning_ja.png)

画像と Markdown を組み合わせたデモワークスペースも同梱しています（[`manuals/demo/product-review/README.md`](manuals/demo/product-review/README.md)）。

![ライトノベルのプロット検討デモ](manuals/screenshot_readme_light_novel_plot_ja.png)

キャラクターシートを参照しながら物語を組み立てるデモもあります（[`manuals/demo/light-novel/README.md`](manuals/demo/light-novel/README.md)）。

## 基本概念

キャンバスは思考や調査を行う**一時的なワークベンチ**です。  
ワークベンチ上で情報を整理・推敲した結果、完成した成果物は個別の Markdown や画像ファイル、Marp プレゼンスライドとしてエクスポートして活用します。

### ノードの種類

- **テキストノード (Text)**: メモ、Markdown テキスト、AI の回答などを記録するノードです。AI が生成したノードは生成元のプロンプト（`originalPrompt`）と自動生成されたサマリーを保持します。
- **画像ノード (Image)**: 取り込んだローカル画像ファイル、または AI が生成した画像ノードです。生成画像は生成プロンプト（およびプロバイダー・モデル情報）を保持し、別のテキスト生成や画像生成の参照コンテキストとしても利用できます。

## 画面構成

ライトテーマを基調とした **Canvas-First / Low-Chrome** な UI を採用しており、常設サイドバーや多層ドロワーを置かず画面の大部分をキャンバスとして開放しています。

- **メイン Canvas**: パンおよび広域ズーム（`0.1`〜`4.0`）に対応した無限キャンバス。ノードの配置・リサイズ、左右コネクタによる有向エッジ連結、ファイルのドラッグ＆ドロップ、右クリックメニューからの各種操作を行います。
- **上部フローティングバー**: キャンバス上部に配置された控えめなツールバーです。`+ メモ`（新規テキストノード追加）、`整頓`（オートレイアウト）、`開く`（Canvas JSON 読込）、`保存`（Canvas JSON 保存）、`設定`（設定モーダル）を実行できます。右上には現在のズーム率（クリックで全体表示 `fitView`）を表示します。
- **下部コマンドドック ＋ コンテキストストリップ**:
  - **コンテキストストリップ**: 選択中ノードと上流チェーンから収集された「テキスト件数 / 画像枚数」をリアルタイムに表示します。分岐合流やループ検出により上流探索が停止した場合は警告チップを表示します。
  - **コマンドドック**: `テキスト` モード（LLM テキスト生成）と `画像` モード（マルチプロバイダー画像生成）を切り替え、プロンプトを入力して送信（`Ctrl+Enter` / `Cmd+Enter` 対応）します。`画像` モードではリクエスト単位でプロバイダーを一時的に切り替えられます。生成中はローディング表示となり多重送信を防ぎます。
- **オンデマンドオーバーレイ（必要な時だけ開く UI）**:
  - **テキストノード詳細エディタ（NodeInspector）**: テキストノードをダブルクリック（または右クリックメニューから「編集」）すると右側からスライドインします。Markdown の「編集」「プレビュー」切替、全文編集、サマリーの編集・再生成、元プロンプトの入力欄追記、単体 `.md` エクスポートが可能です。
  - **画像ライトボックス（ImageLightbox）**: 画像ノードをダブルクリック（または右クリックメニューから「拡大表示」）すると拡大オーバーレイを表示します。生成プロンプト全文の確認、入力欄への追記、単体画像エクスポートが可能です。
  - **設定モーダル（SettingsModal）**: `LLM 設定` / `画像生成` / `キャンバス管理` の 3 タブ構成で、各種 API 設定や `キャンバスを初期化（Clear Canvas）` を行えます。
  - **トースト通知・確認ダイアログ**: 操作の完了やエラーは画面内のトースト通知で非ブロッキングに表示され、破壊的操作（Clear Canvas）には確認ダイアログが表示されます。

## 主な使い方 / ユースケース（逆引きガイド）

### キャンバス基本操作

- **キャンバスを移動・拡大縮小する**: ドラッグでパン、マウスホイールで `0.1`〜`4.0` 倍のズームが可能です。右上のズーム率ボタンをクリックするとキャンバス全体を表示（`fitView`）します。
- **ノードを選択・解除する**: クリックで単一選択、`Shift` + クリックやドラッグ矩形選択で複数選択、背景クリックで選択解除します。
- **ノードやエッジを削除する**: 対象を選択して `Delete` / `Backspace` キーを押すか、右クリックメニューから削除します。
- **キャンバスを初期化する（Clear Canvas）**: 上部バーの「設定」→「キャンバス管理」タブから「キャンバスを初期化（Clear Canvas）」を実行します（確認ダイアログで確定した場合のみ全ノード・全エッジを消去）。

### テキストノード・詳細編集

- **新規メモを追加する**: 上部バーの「+ メモ」をクリックすると、キャンバス中央に空のテキストノードを追加します。
- **カード上で内容を確認する**: サマリーが設定されている場合はサマリーを、未設定の場合は本文を行数制限付きで表示します。AI 生成ノードの場合はカード下部に生成元プロンプトが表示されます。
- **全文編集・Markdown プレビュー・サマリー再生成**: テキストノードをダブルクリックして詳細エディタを開き、「編集」「プレビュー」を切り替えて確認・編集します。別のテキストノードへ切り替えるかエディタを閉じると、編集内容は自動的に確定されます。
- **生成元プロンプトを再利用する**: カード下部または詳細エディタの元プロンプトをクリックすると、コマンドドックの既存入力を消さずに末尾へ追記（既存入力がある場合は `\n\n` 区切り）されます。

### 有向エッジ連結とコンテキスト収集

- **ノード同士を有向エッジで繋ぐ**: ノード左右の接続ハンドルをドラッグして別ノードのハンドルへ接続します。直接・間接を問わずループを形成する接続は作成前に検出して拒否・通知されます。
- **上流コンテキストを自動で集める**:
  - **0 件選択時**: コマンドドックの入力プロンプトのみを送信します。
  - **1 件選択時**: 選択ノードから上流を遡り、源流 → 選択ノードの順でテキストと参照画像を分離収集します。
  - **複数選択時**: 接続関係に基づくトポロジカル順（未接続分は選択/配置順）で分離収集します。
  - 探索中に分岐合流やループを検出した場合は、その地点で上流探索を停止し、コンテキストストリップに警告を表示します。

### LLM テキスト生成・Vision・自動サマリー

- **コンテキスト付きで AI に質問する**: 対象ノードを選択（または未選択）の状態で、コマンドドックを `テキスト` モードにしてプロンプトを送信します。
- **画像を読み取って質問する（Vision）**: コンテキストに画像ノードが含まれる場合、Vision マルチモーダル入力として OpenAI 互換 API へ送信されます（Vision 対応モデルの設定が必要です）。
- **ローカル LLM を利用する**: API キーが空欄の場合、`Authorization` ヘッダーを省略してリクエストするため、認証不要のローカル LLM サーバーにも接続できます。
- **自動サマリー**: テキスト生成成功後、新規テキストノードが追加され、本文の自動サマリーが付与されます（サマリー生成に失敗した場合も本文は維持され、エラー通知が表示されます）。

### マルチプロバイダー画像生成

- **プロバイダーを選んで画像を生成する**: コマンドドックを `画像` モードに切り替え、プロバイダー（OpenRouter / OpenAI / Google / xAI）を選んでプロンプトを送信します。ここでのプロバイダー選択はリクエスト単位の一時切替であり、設定ファイルのデフォルトプロバイダーは書き換わりません。
- **参照画像付きで画像を生成・編集する**: キャンバス上の画像ノード（およびテキスト指示）を選択した状態で `画像` モードから生成を実行すると、参照画像として送信されます（OpenAI は最大 5 枚、xAI は 1 枚）。
- **ローカル保存と拡大表示**: 生成された画像は衝突しないファイル名で `downloadPath` にローカル保存され、画像ノードのみが 1 つキャンバスに追加されます。ダブルクリックでライトボックス拡大表示でき、カード下部のプロンプトクリックで入力欄へ非破壊追記できます。

### ファイルの取り込み・整頓・保存・エクスポート

- **ファイルをドラッグ＆ドロップで取り込む**: OS のファイルマネージャからキャンバス上へ直接ドロップしてノード化できます。
  - `.txt` / `.md`: 新規テキストノードとして配置
  - `.png` / `.jpg` / `.jpeg` / `.webp`: `downloadPath/Import/` へ衝突しないファイル名でコピーし、新規画像ノードとして配置（非対応拡張子はエラー通知）
- **散らかったノードを整頓する**: 上部バーの「整頓」をクリックすると、エッジの接続関係を保ったまま左→右（`LR`）方向へ自動再配置（オートレイアウト）します。
- **キャンバス全体を保存・再開する**: 上部バーの「保存」で任意の `.json` ファイル（version `1.1`）へ保存し、「開く」から読み込みます。既存の `v1.0` / `v1.1` キャンバス JSON との互換性を維持しています。
- **成果物をエクスポートする**:
  - **単体 Markdown（`.md`）**: テキストノードの右クリックメニューまたは詳細エディタから出力
  - **単体画像ファイル**: 画像ノードの右クリックメニューまたはライトボックスから出力
  - **Marp スライド（`.md`）**: 複数ノードを選択して右クリック（または単一ノードの右クリックから上流チェーンを含めて）→「スライドとしてエクスポート (Marp)」で、`---` 区切り・画像記法埋め込み済みの Markdown を出力

## 設定と構成

上部バーの「設定」から設定モーダルを開き、変更後に「保存」をクリックします。

### LLM 設定
OpenAI 互換 API（`POST {baseURL}/chat/completions`）を提供する任意のプロバイダー（OpenRouter, OpenAI, Ollama, LocalAI 等）を利用できます。
- **Base URL**: API エンドポイント（例: `https://api.openai.com/v1`、`http://localhost:11434/v1`）
- **Model**: 使用するモデル名（画像入力を行う場合は Vision 対応モデルを指定）
- **API Key**: プロバイダーの API キー（ローカル LLM 等の場合は空欄可）
- **System Prompt**: 共通のシステム指示（空欄時は既定のシステムプロンプトを使用）
- **サマリー最大文字数目安**: 自動サマリー生成時の目安文字数

### 画像生成
- **デフォルトプロバイダー**: OpenRouter / OpenAI / Google / xAI から選択
- **画像保存先ディレクトリ**: 生成画像およびインポート画像の保存先（デフォルト: `Image/`）
- **プロバイダー別設定**: 4 プロバイダーそれぞれの Base URL（OpenRouter / OpenAI）・Model・API Key を個別に設定・保持します。デフォルトプロバイダーを切り替えて保存しても、他プロバイダーのキーや設定は失われません。

### キャンバス管理
- **キャンバスを初期化（Clear Canvas）**: 確認ダイアログを経て現在のノード・エッジ・選択状態を全消去します（ディスク上の保存済み画像ファイルは残ります）。

## 保存データとセキュリティ

- **アプリ設定 (`config.json`)**:
  - Windows: `%APPDATA%\fm-doc-canvas\config.json`
  - macOS: `~/Library/Application Support/fm-doc-canvas/config.json`
  - Linux: `~/.config/fm-doc-canvas/config.json`
  - 旧フラット形式（`imageGen.baseURL` / `model` / `apiKey`）の `config.json` は読み込み時にプロバイダー別構造へ自動マイグレーションされます。
  - **セキュリティ注意**: API キーは `config.json` のみに保存され、Canvas JSON・ログ・エラーメッセージには一切出力されません。設定ファイル自体は平文保存されるため取り扱いにはご注意ください。
- **画像ストレージとパス検証**:
  - 生成画像は指定の `downloadPath`（デフォルト `Image/`）、D&D インポート画像は `downloadPath/Import/` に保存されます。
  - 画像の解決・読み込み・エクスポート時にはパストラバーサル（`..`、絶対パス、`downloadPath` 外への逸脱）が拒否されます。
- **Canvas データ**:
  - 「保存」で明示的に保存した任意の `.json` ファイルに記録されます（API キー等の秘匿情報は含まれません）。未保存のままアプリを終了すると作業内容は失われます。

## 開発環境のセットアップ

このプロジェクトでは、ツールチェーンのバージョン管理に `mise` を使用しています（`go`, `npm`, `wails` 等は `mise` 経由で実行します）。

### 1. 前提条件
- [mise-en-place](https://mise.jdx.dev/getting-started.html) のインストール

### 2. ツールチェーンのインストール
```bash
# ツールチェーン（Go, Node.js, Wails CLI）のインストール
mise install
```

### 3. 開発モードでの実行
```bash
mise run dev
```

### 4. テスト・フロントエンドビルド・アプリビルド
```bash
# バックエンド単体テスト (Go)
mise run test-backend

# フロントエンド単体テスト (Vitest)
mise run test-frontend

# フロントエンド型チェック＆ビルド
mise run build-frontend

# Wails デスクトップバイナリのビルド
mise run build
```

## プロジェクト構造

- `app.go`, `main.go`: Wails アプリケーションのエントリポイントおよびバインド用ファサード
- `backend/`: Go によるバックエンドサービス（設定管理・LLM/Vision・4プロバイダー画像生成・画像アセット/パス検証・ファイル入出力）および単体テスト
- `frontend/`: React + TypeScript + Tailwind CSS による Canvas-First UI、Zustand ストア、純粋関数ユーティリティおよび単体テスト
- `build/`: アプリケーションのアイコンやインストーラー設定
- `docs/`: 要件定義・仕様・設計ドキュメント
